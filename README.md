# Narrative Interact v1.1.0

[English README is here](README_EN.md)

ローカルLLMで動くインタラクティブフィクションシステム。  
ジャンルとタイトルを入力するだけで、LLMがGM（ゲームマスター）として物語を自動生成する。プレイヤーは主人公として自由に行動を入力し、その結果に応じてGMが物語を進める。

あらかじめ用意されたシナリオを読むのではなく、LLMが生成した物語に主人公として介入し、自分の行動によって展開を変化させながら物語を進めるシステムです。プロットへの拘束度を選べるため、物語の流れを重視したプレイから、展開を積極的に変えるプレイまで試せます。

## 開発経緯

ローカルLLMの存在を知ったのは、OllamaでAI VTuberを作ったことがきっかけだった。その後LM Studioを知り、プロンプトエンジニアリングで小説を書かせることにハマった。

ある日、LM StudioのLLMに「あなたはTRPGのGMです。」の一行だけでTRPGもどきをやってみたら、これが想像以上に楽しかった。「LM Studioでもっと遊べるものを作りたい」という動機からこのシステムの開発が始まった。

## 特徴

- **完全ローカル動作**：LM Studio経由でローカルLLMを使用。外部APIは不要
- **ジャンル・タイトル自由**：日常、ミステリー、ファンタジー、ホラーなど何でも指定可能
- **プロット自動生成**：ゲーム開始時にLLMが物語の骨格（登場人物・葛藤・反転・エンディング）を設計する
- **ダイス判定**：行動の成否をダイスで決定。成功・失敗がGMの描写に反映される
- **セーブ・ロード**：途中でセーブして後から再開できる
- **物語の軸を選択**：プロット拘束度を4段階から選べる
- **GMの一言**：転換点でGMがシニカルな一言コメントを返す場合がある。あり/なしを選択制
- **転換点描写強化**：物語の転換点で自動的に詳細な描写を促す（文字数制限解除）。転換点ターンのGM本文はマゼンタ色で表示される（GMキャラ設定に関わらず発動）

## 遊び方

### 1. 起動とゲーム設定

```bash
python main.py
```

起動後、以下を順番に入力する。

```
ジャンル: ミステリー
タイトル: 消えた遺言状
```

続いて物語の軸を選択する。

| 選択 | モード | 内容 |
|------|--------|------|
| 1 | プロット参照・強拘束 | 反転・選択・失敗をプロット通りに強制回収する。プレイヤーの行動の自由は維持しつつ、主要なプロット要素を必ず回収する。**初めてならこれを推奨** |
| 2 | プロット参照・適応 | プロットに添うが逸脱プレイ可能。逸脱が大きい場合は現在地で物語を再構成し、着地まで誘導する。 |
| 3 | プロット参照・自由 | プロットは参考情報。逸脱しても構わない。プレイヤーの自由行動を最優先にしたい場合に向く。 |
| 4 | プロットなし・即興 | プロットを生成せずGMが即興で物語を作る。展開の方向性に制約がない。 |

続いてGMの一言コメントのあり/なしを選択する。

| 選択 | 動作 |
|------|------|
| あり（シニカル） | 転換点でGMがシニカルな一言コメントを返す。「まあ、そういう手もあるか」「…そうですか」 |
| なし | GMは黙って進行する（従来の動作） |

**モードの違いについて**

各モードはGMへのプロット制約の強さが異なります。同じプレイヤー行動でもモードによって結末が大きく変わることがあります。これは設計上の意図的な差異です。

- **強拘束**：システムがGMにビート（場面の節目）をターンごとに注入し、プロット回収を強制する
- **適応**：逸脱検出をターンごとに行い、逸脱が一定以上続くと新プロットをLLMに再生成させてbeat制御で着地させる
- **自由**：ビートを誘導形でGMに提示するが、プレイヤーが無視しても強制しない
- **即興**：プロット生成もビート注入も行わず、GMの出力のみで物語が進む

**GMの一言について**

GMの一言コメントは物語本文の生成とは独立した別の呼び出しで動作する。物語のルール・モード・ビート進行には一切影響しない。

転換点（プロット上の節目やLLMが転換点と判定したターン）のみGMが一言コメントを発する。毎ターン出るわけではないため、出たときに意味が生まれる。物語のジャンルや展開によっては転換点が少なく、一言コメントがほとんど出ない場合もある。

コンソール表示は `GM:` が青色、コメント本文がシアン色で `GM: まあ、そういう手もあるか` のように表示される。

### 2. 行動入力

GMの描写を読んで、主人公として行動を入力する。

```
> 机の引き出しを開ける
> 老人に話しかける
> 窓から外を見る
```

行動は自由。GMはプレイヤーの行動を否定せず、結果として世界を変化させる。

### 3. ダイス判定

行動によってはダイス判定が発生し、成否がGMの描写に反映される。難易度は起動時に選択できる（易しい・標準・厳しい）。

出目はPythonの`random.randint(1, 20)`で決定される。AIが判断するのは「判定が必要か」「行動のリスクと不確実性の分類」のみで、出目と難易度の数値にはAIは一切関与しない。

### 4. エンディング

物語の主要な葛藤が解消されるとGMがエンディングを描写して物語が終わる。

## 動作環境

- Python 3.10以上
- [LM Studio](https://lmstudio.ai/) （ローカルサーバーとして起動）
- 対応OS：Windows / macOS / Linux
- 推奨モデル：Gemma4 12B
- 推奨コンテキスト長：32,768トークン以上（入力側：システムプロンプト約10,000トークン＋物語進行の会話履歴で計約30,000トークン。出力側：`MAX_TOKENS`はGMの1回の生成上限で、実際の出力は数百〜1,000トークン程度）

## セットアップ

バイナリ配布はありません。ソースコードをそのままダウンロードして実行してください。

```bash
git clone https://github.com/naoki-Kamishiro/narrative-interact.git
cd narrative-interact
pip install -r requirements.txt  # openai / json-repair
```

`config.py` でLM StudioのエンドポイントとモデルIDを設定する。

```python
# config.py
LM_STUDIO_URL = "http://localhost:1234/v1"  # LM StudioのデフォルトURL
MAX_TOKENS    = 1024                         # 1回の生成で出力する最大トークン数
TEMPERATURE   = 0.85
```

モデルIDの指定は不要（LM Studioはロード中のモデルを自動で使用する）。  
コンテキスト長（32,768トークン以上を推奨）はLM Studio側のモデル設定で変更すること。

## 自動プレイ（デバッグ用）

プレイヤー入力もLLMが担当するモード。プロンプト検証・挙動確認に使用する。

```bash
python main.py --normal           # 通常モード
python main.py --deviate          # 逸脱モード（GM制約を意図的に超える行動）
python main.py --debug            # 手動プレイ＋デバッグ出力あり
python main.py --normal --batch 5   # バッチ実行（ランダムなジャンル・タイトルで5回連続）
python main.py --deviate --batch 5  # 逸脱モードでバッチ実行
```

`--batch N` を指定すると、LLMがジャンルとタイトルを毎回自動生成してN回連続で実行し、1回ごとにJSONファイルを保存する。物語の軸は起動時に1回だけ選択し、難易度は標準固定。

プレイヤーLLMの挙動はモデル・ジャンル・プロット設定に大きく依存する。特にジャンル制約で戦闘・探索・謎解きをすべてオフにした場合（群像ドラマ・日常など）、プレイヤーLLMが「見つめる」「近づく」などの行動を繰り返すループに陥りやすくなる。これはシステムのバグではなく、行動の選択肢が狭いジャンルにおけるモデルの素の挙動である。

自動プレイを研究・観察目的で使う場合、ダークファンタジー・ホラー・ミステリーなど探索や謎解きのあるジャンルの方が挙動の多様性が出やすい。

## モデルの性能限界（Gemma4 12Bでの妥協点）

より高性能なモデルでは改善する可能性がある。各項目の状態は以下の3区分で示す：
- **軽減策実装済み**：プロンプトや処理を追加し、発生頻度の低下を狙っている
- **残存する制約**：対策後も一定の頻度で発生する
- **モデル依存**：対策済みだが完全な解消はモデルの能力に依存する

**軽減策実装済み（ほぼ抑制されているが確率的に発生）**

- **毎ターン問いかけで締める**：「あなたはどうしますか？」「次はどこへ行きますか？」とGMが毎回締めくくろうとする。禁止ルールで抑制済み
- **選択肢の箇条書き提示**：「A. 逃げる　B. 戦う　C. 交渉する」のように選択肢を列挙する。禁止ルールで抑制済み
- **ダイス判定の無視・書き換え**：失敗判定なのに実質成功の描写をする、または成功判定を直後に無効化する。整合性ルールで抑制済み
- **局面への沈み込み**：同じ場面・同じ対象を延々と掘り下げ、物語が前進しない。反復制限ルールで抑制済み
- **NPCによる主人公内面の代弁**：NPCが「あなたは本当に成長しましたね」のように主人公の行動の意味をテーマ的に解説する台詞を言う。禁止ルールで抑制済み
- **エンディング早発**：「帰宅した」「休んだ」など日常描写でエンディングにしてしまう。条件の詳細化で抑制済み

**残存する制約（対策後も一定頻度で発生）**

- **地の文への内面・意味付けの混入**：「誇りが宿る」「覚悟が固まる」のような感情・内面描写や、「これは○○を意味する」という解釈をGMが書いてしまう。禁止ルールで抑制しているが、長い物語の後半やクライマックスで崩れることがある
- **着地点の先取り**：プロットのendingフィールドに記された動機語・テーマ語（「執着」「守りたかったもの」等）を、エンディング前のNPCの台詞や地の文で使い始める。禁止ルールとendingフィールドへの動機語排除指示で抑制しているが、ミステリーなど動機が物語の核となるジャンルで発生しやすい

**モデル依存（対策済みだが完全な解消はモデルの能力に依存）**

- **設定の追加先行**：行動・判定の結果を描写するたびに新しい設定・脅威・登場人物を追加し、既出の情報から結果を導かない。物語の複雑さより設定量が増える印象になりやすく、因果関係が薄くなる。抑制ルールを追加済み
- **結果の効果量が均一に大きい**：成功・失敗・決定的成功・重大失敗のいずれでも、物語全体を揺るがすような大規模な展開を起こしやすい。出目の強弱が結果の規模に反映されず、選択の手応えが単調になることがある

## 既知の不具合

- **自動プレイ時のループ**：プレイヤーLLMが「握る→握りしめる→力を込める」のように動詞を微妙に変えながら同じ対象への行動を繰り返すことがある。プレイヤープロンプトに「同じ対象への行動が動詞を変えながら3回続いた場合も別の対象・場所へ切り替えること」を追加して抑制済み。完全な解消はモデル依存。
- **プレイヤーLLMによる内面描写**：自動プレイ時にプレイヤーLLMが「覚悟を決める」「感謝の気持ちを伝える」のような内面行動を出力することがある。プレイヤープロンプトに「外から観察できない内面行動は出力しないこと」を追加して抑制済み。
- **世界観外アイテムの持ち込み**：自動プレイ時にプレイヤーLLMが物語の世界観に存在しないアイテムや手段を持ち出すことがある（例：医療ホラーで銃を使う）。プレイヤープロンプトに「世界観外のアイテム・手段は使用しないこと」を追加して抑制済み。
- **失敗対象への固執**：自動プレイ時にプレイヤーLLMが同じ対象への行動を繰り返し失敗しても、別の対象や場所に切り替えず同じ対象に試行し続けることがある。プレイヤープロンプトに「同じ対象に2回連続で失敗したら別の対象へ切り替えること」を追加して抑制済み。
- **プレイヤーLLMによる対象の言い換えループ**：自動プレイ時にプレイヤーLLMが「兵士A」「重装兵」「前方の兵」のように対象名を毎回微妙に変えながら、実質的に同じ集団への同じ行動を繰り返すことがある。既存の「同じ対象への3回連続で別の場所へ移動」ルールは個別対象を判定するため、集団を相手にした場合は抜け穴になる。完全な解消はモデル依存。
- **フック回収（closing）がエンディングで省略されやすい**：冒頭フックの回収（hook.closing）がエンディング・エピローグで描写されないことがある。GMプロンプトの【プロット】セクションと【末尾の回収と余韻】セクションの両方に「着地点の描写に含めること」を指示して抑制済み。完全な解消はモデル依存。
