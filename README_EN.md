# Narrative Interact

An interactive fiction system that runs on a local LLM via LM Studio.

You specify a genre and a title — the AI generates the plot, and you play through it by typing actions in natural language.

Rather than reading a pre-written scenario, you intervene in a story generated by the LLM, shaping its course through your actions as the protagonist. You can choose how tightly the story follows its plot — from playing with the narrative flow to actively changing it.

---

## What it does

When you start a session, the system automatically generates a plot: protagonist, characters, conflicts, twists, key choices, and an ending. The GM (Game Master) knows this plot but never reveals it directly.

You move the story forward by typing actions — one at a time, in plain text.

```
> Step forward.
> Look the elf in the eye.
> Reach out toward the membrane of light.
```

Each action is evaluated for uncertainty and risk. If a dice roll is needed, a d20 is thrown. The GM then narrates the outcome — success or failure — and the story branches accordingly.

The story ends when the plot reaches its conclusion. The GM decides when that is.

---

## Features

- **Auto plot generation** — Genre and title are the only inputs needed. The system generates the full narrative structure before play begins.
- **Dice resolution** — Actions are automatically judged for whether a roll is needed. Difficulty is computed locally from two axes (risk × uncertainty), not by the LLM.
- **Beat injection (strong mode)** — Plot beats (twists, failures, character appearances, key choices) are silently injected into GM instructions at the right timing. The player never sees them.
- **Ending detection** — The GM outputs `【エンディング】` when the story concludes. An epilogue is then generated automatically.
- **Save / Load** — Sessions are saved as JSON. You can resume any session later.
- **Auto-play mode** — The system can play itself, useful for testing and evaluation.

---

## Requirements

- Python 3.10+
- [LM Studio](https://lmstudio.ai/) running a local LLM on `localhost:1234`
- A model capable of following complex Japanese instruction prompts

> **Note:** The GM system prompt is written in Japanese. The model needs to handle Japanese instructions reliably. Models in the 7B–14B range vary significantly in quality for this task.

## Setup

```bash
git clone https://github.com/naoki-Kamishiro/narrative-interact.git
cd narrative-interact
pip install -r requirements.txt
```

Start LM Studio and load a model. Make sure the local server is running on port `1234`.

Edit `config.py` to configure the endpoint:

```python
# config.py
LM_STUDIO_URL = "http://localhost:1234/v1"  # Default LM Studio URL
MAX_TOKENS    = 1024                         # Max tokens per generation
TEMPERATURE   = 0.85
```

No model ID is required — LM Studio automatically uses whichever model is currently loaded.  
Context length (32,768+ tokens recommended) is set on the LM Studio side, not here. As a reference: the input side uses roughly 10,000 tokens for the system prompt plus conversation history as the story progresses (total around 30,000 tokens). `MAX_TOKENS` is the per-generation output limit; actual GM output is typically a few hundred to around 1,000 tokens.

Then run:

```bash
python main.py
```

## Usage

On startup, you will be prompted for:

1. **Genre** — e.g. `Fantasy`, `Mystery`, `Sci-Fi`
2. **Title** — e.g. `The Elf and the Old Man`
3. **Plot mode** — choose from 4 options (see below)
4. **Difficulty** — `easy` / `normal` / `hard`

**Plot modes:**

| # | Mode | Description |
|---|------|-------------|
| 1 | Plot reference · free | Plot is advisory only. Deviation is fine. Best for prioritizing player freedom above all else. **Experimental — may end at the 40-turn limit if the story does not converge** |
| 2 | Plot reference · loose | Follows the plot but allows free play and deviation. Balances narrative flow with player freedom. **Recommended for first-time play** |
| 3 | Plot reference · strict | Beats, twists, and failures are force-injected on schedule. Player freedom is maintained, but major plot elements are always resolved |
| 4 | No plot · improv | No plot is generated; the GM improvises freely. Every run produces a completely different story. **Experimental — may end at the 40-turn limit if the story does not converge** |

After that, the opening scene is generated and you begin.

**In-game commands:**

| Command | Description |
|---------|-------------|
| `/save` | Save the current session |
| `/load` | Load a saved session |
| `/hint` | Show 3–4 suggested actions |
| `/retry` or `/r` | Regenerate the last GM response |
| `/help` or `/h` | Show command list |
| `/quit` | Quit without saving |

## How it works

### Plot generation

Before play starts, an LLM call generates a complete plot structure in JSON:

- Protagonist wound / surface goal / deep desire
- Characters and their roles
- Misconceptions the player starts with
- Failures and twists (with timing tags: early / mid / climax)
- Key choices with costs
- Climax setting and ending

This plot is passed to the GM as a hidden system prompt. The GM knows it; the player doesn't.

### Dice resolution

Every player action is sent to a separate LLM call that judges whether a roll is needed. If yes, it returns `risk` and `uncertainty` (each `low` / `mid` / `high`). Difficulty is then computed locally:

```
difficulty = base(9) + risk_value + uncertainty_value + preset_offset
```

The LLM never outputs a difficulty number directly — this prevents prompt-length bias inflating difficulty.

The actual die roll is `random.randint(1, 20)` in Python. The LLM has no influence over the result — it only classifies the action, never touches the numbers.

### Beat injection (strong mode)

In strong mode, plot beats are queued at startup. Each turn, the current beat is appended to the GM's user message as a hidden scene directive. The player sees the result in the narration; they never see the directive itself.

Character beats are confirmed by checking whether the character's name appears in the GM's response. Other beat types are trusted after one injection and the pointer advances.

## Auto-play mode

For testing and evaluation, the system can play itself — the player role is also handled by an LLM.

```bash
python main.py --normal           # auto-play, normal mode
python main.py --deviate          # auto-play, deviate mode (intentionally pushes against GM constraints)
python main.py --debug            # manual play with debug output
python main.py --normal --batch 5  # batch mode: run 5 sessions with random genres and titles
python main.py --deviate --batch 5 # batch mode, deviate variant
```

`--batch N` runs N consecutive sessions. The LLM generates a different genre and title for each session. Plot mode is selected once at startup and shared across all sessions. Difficulty is fixed at normal. Each session is saved as a JSON file on completion.

Player LLM behavior varies significantly depending on the model, genre, and plot settings. When genre constraints disable combat, exploration, and mystery elements simultaneously (e.g. ensemble drama, slice-of-life), the player LLM tends to fall into repetitive loops — actions like "stare at", "move closer", or "look toward" repeated with slight variations. This is not a system bug; it reflects the model's natural behavior when available action space is narrow.

For research or observation purposes, genres with exploration or mystery elements (dark fantasy, horror, mystery) tend to produce more varied player behavior.

## Model limitations (Gemma4 12B)

Higher-capability models may improve on these. Each item is categorized as follows:
- **Mitigation implemented**: prompts or processing have been added to reduce frequency
- **Residual constraint**: occurs at some frequency even after mitigation
- **Model-dependent**: mitigated but complete suppression depends on model capability

**Mitigation implemented (largely suppressed, but may still occur)**

- **Ending prompt at every turn**: The GM tends to close each turn with "What will you do?" or "Where will you go next?" Suppressed by rule.
- **Bullet-point choices**: The GM may list options as "A. Flee  B. Fight  C. Negotiate". Suppressed by rule.
- **Ignoring or reversing dice results**: The GM may describe near-success on a failure roll, or immediately undercut a success. Suppressed by consistency rules.
- **Scene stagnation**: The GM may linger on the same location or object across many turns without advancing the story. Suppressed by repetition-limit rules.
- **NPC as thematic spokesperson**: An NPC may say something like "You've really grown" — interpreting the protagonist's actions in thematic terms. Suppressed by rule.
- **Premature ending**: The GM may end the story on a mundane beat like "returned home" or "took a rest". Suppressed by detailed ending conditions.

**Residual constraints (occur at some frequency even after mitigation)**

- **Emotional or interpretive language in narration**: The GM may write phrases like "pride filled his chest" or "her resolve hardened" — emotional or internal descriptions that should be conveyed only through action and expression. Suppressed by explicit prohibition rules, but tends to resurface in later turns and at climactic moments.
- **Plot ending foreshadowed early**: Motivation words or theme language from the plot's ending field (e.g. "what he wanted to protect", "obsession") may appear in NPC dialogue or narration before the ending. Suppressed by prohibition rules and by excluding motivation language from the ending field in plot generation. More likely to occur in genres where motivation is central, such as mystery.

**Model-dependent (mitigated but complete suppression depends on model capability)**

- **New settings added before existing ones are used**: When narrating the result of an action or dice roll, the GM tends to introduce new settings, threats, or characters rather than deriving the outcome from information already established. This can make the story feel like an accumulation of new elements rather than a connected chain of cause and effect. Mitigation rule added.
- **Uniform effect size regardless of roll**: Whether the roll is a critical success, normal success, failure, or critical failure, the GM tends to trigger large-scale story-wide events. The magnitude of outcomes does not scale with the die result, which can make choices feel repetitive. Mitigation rule added.

## Known issues

- **Auto-play action loops**: The player LLM may repeat actions on the same target by slightly varying the verb (e.g. "grip" → "grip tightly" → "apply force"). A rule requiring the player to switch targets or locations after 3 consecutive actions on the same object has been added to reduce this. Complete suppression depends on the model.
- **Player LLM inner-state output**: In auto-play mode, the player LLM may output internal actions such as "steel myself" or "accept the situation". A rule requiring all actions to be externally observable (physical, verbal, or movement) has been added to the player prompt.
- **Out-of-world items**: The player LLM may introduce items or tools that do not exist in the story's setting (e.g. a gun in a medical horror scenario). A rule prohibiting items outside the established world has been added to the player prompt.
- **Fixation on failed targets**: In auto-play mode, the player LLM may keep attempting the same target after repeated failures. A rule requiring the player to switch targets after 2 consecutive failures on the same object has been added.
- **Target-name variation loops**: In auto-play mode, the player LLM may repeat essentially the same action against the same group of enemies while slightly varying the target name each turn (e.g. "soldier A", "heavy infantry", "the man in front"). The existing rule that requires switching targets after 3 consecutive actions on the same object does not catch this, since each name is treated as a different target. Complete suppression depends on the model.
- **Opening hook not resolved at ending**: The closing hook (hook.closing) defined in the plot may be omitted from the ending or epilogue. Both the plot section and the ending-note section of the GM prompt now include an explicit instruction to incorporate it into the ending scene. Complete suppression depends on the model.
